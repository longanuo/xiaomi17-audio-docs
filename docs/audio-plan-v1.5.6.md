# 小米17外放音质与音效调校方案 v1.5.6

作者：林河。设备：小米17标准版，代号 `pudding`。文档整理日期：2026-10-21。

本文根据本地 v1.5.6 模块文件、v1.5.3 / v1.5.4 说明和现有验证记录整理。配置中可以直接确认的行为、旧版实机观察与当前版本待验证的效果分别说明。

对应的[完整模块文件](../module/)和[打包脚本](../tools/build_module.py)已纳入仓库。`module/` 的初始文件逐字节对应下文列出哈希的正式 v1.5.6 ZIP；重新压缩生成的 ZIP 应使用自身的校验值。

## 1. 调校目标与版本关系

本方案的目标是改善外放的音量衔接、中低音量可听性，以及鼓点的厚度与暖度，同时尽量保持人声清楚。

本地早期方案曾使用 v5.x 编号；后续这条方案使用 v1.5.x 编号，不能仅按版本数字大小判断新旧。当前整理对象为 v1.5.6。

- v1.5.2：低音量补偿基线，旧版记录包含实际运行曲线已加载的证据。
- v1.5.3：在基线上调整部分中低频参数，以鼓点厚度和暖度为目标，听感待验证。
- v1.5.4：延长中低音量补偿，缓解部分播放场景约三至四成音量偏小的问题。
- v1.5.6：沿用 v1.5.4 的音频配置，调整安装条件，仅校验机型，不再限制系统版本。

v1.5.6 没有新增一套调音参数，主要改变是安装条件与相应版本记录。

## 2. 生效路径

模块使用手机现有音频引擎，通过配置覆盖、原厂音效属性和开机校验工作。四份配置在模块中位于 `system/odm/etc/` 对应目录，目标路径为：

- `/odm/etc/audio/audio_effects_config.json`：音量分档和应用场景映射。
- `/odm/etc/dolby/dax-default.xml`：普通 Dolby 路径的调音配置。
- `/odm/etc/dolby/dax-default-spatializer.xml`：Dolby 空间处理路径的调音配置。
- `/odm/etc/audio_policy_engine_stream_volumes_mi.xml`：媒体等音量曲线配置。

`post-fs-data.sh` 在开机早期逐一检查四份配置，必要时执行 bind mount，并核对文件内容与 `vendor_configs_file` 标签。结果写入 `/data/adb/xiaomi17_audio_mod_stage1`。

`service.sh` 等待开机完成后再次检查配置，按开关设置 Dolby / MiSound 状态，并生成自检报告。它没有持续轮询音效状态的循环。

## 3. 音量分档、鼓点与响度补偿

### 音量分档

当前 JSON 保留以下分档：

```json
"volume_levels": [
  { "range": [0, 70], "device_id": "small_mode_speaker" },
  { "range": [71, 130], "device_id": "medium_mode_speaker" },
  { "range": [131, 150], "device_id": "large_mode_speaker" }
]
```

这些数字属于内部音量索引，不能保证与所有系统界面的百分比一一对应。本版没有使用早期 v5.x 扩展 small 档覆盖范围的做法，相关衔接调整沿用 v1.5.4 的 Dolby 配置。

### 鼓点厚度

沿用 v1.5.3 的修改：在已有的小、中音量和部分默认外放调音项中，调整 `audio-optimizer-bands` 的 141 Hz、234 Hz 和 328 Hz 增益编码值。左右声道使用相同增量，保留原有左右校准差。

上述编码与 dB 的换算尺度尚未独立验证。因此，不能将编码增量直接写成“增加若干 dB”，也不能据此宣称已经改善低频下潜、解析力或人声清晰度。

大音量 large 档、47 Hz 频段以及相关空间渲染与保护参数按既有基线保留；最终效果取决于系统实际加载的路径。

### 中低音量补偿

沿用 v1.5.4 对 `music / SPEAKER` 曲线七个点的调整。相对 v1.5.2 / v1.5.3，曲线索引 40 额外增加 2 dB，47、53、60、66 各增加 3 dB，73 增加 2 dB，80 增加 1 dB；87 起恢复旧版曲线。

这里的曲线点索引按配置使用 0–100 的尺度，与上面的 0–150 音量分档索引不同。最大额外补偿为 3 dB，指软件曲线差值，不等于实测声压或固定的主观响度提升。

此补偿作用于外放媒体曲线，会影响音乐、视频和游戏等场景；没有按视频逐条做响度归一化。旧版记录中的部分短视频音轨存在额外衰减，其来源尚未确定，本方案不承诺消除所有视频之间的响度差异。

## 4. 默认开关与修改范围

`audio_tuning.conf` 默认内容包括：

```ini
ENABLE_DOLBY_MUSIC=1
DOLBY_PROFILE=3
ENABLE_MISOUND_MUSIC=1
ENABLE_SPATIAL_ANCHOR=0
```

- Dolby 开关启用时设置 `persist.audio.dolby.profile`，默认值为 3。应用场景或系统仍可能影响最终工作档，需以运行日志为准。
- MiSound 状态仅在脚本确认指定原厂配置中存在 `misoundfx` 时设置。
- 空间声总开关默认不锁定。是否进入空间处理路径，还取决于系统设置、应用与实际播放状态。
- `system.prop` 包含 `ro.vendor.audio.sfx.harmankardon=1` 兼容标记。该标记本身不构成官方调音、认证或声音效果的证明。

模块没有携带小米10S音效库、DSP 二进制、ACDB、功放校准或 mixer 替换文件；脚本不写入 mixer 控制项。保留保护配置并不代表任何系统和使用条件下都已经验证。

## 5. 安装条件与兼容性

安装脚本精确要求 `ro.product.device=pudding`。系统版本、Android API 和 ROM 渠道不作为安装放行条件；包内配置文件存在性、权限与标签检查仍然保留。

本版采用整份配置覆盖。若新系统修改了同一文件中的其他音频条目，安装本版也会覆盖那些条目。因此，“允许安装”“文件覆盖成功”“音频服务加载成功”和“听感符合目标”需要分别验证。

## 6. 验证依据与当前状态

现有 v1.5.6 电脑端验证记录包括：

- 四份音频配置与 v1.5.4 一致。
- 七个 shell 脚本的语法检查通过。
- 模拟安装检查覆盖不同系统版本、错误机型、包含 pudding 的非精确机型值和缺失机型等情况。
- 检查保留标签失败、缺失配置文件等错误处理。
- ZIP CRC 与文件内容检查通过。

这些是既有电脑端检查记录，不是本次重新完成的刷机或声学测试。记录明确注明没有执行 v1.5.6 实机安装；旧版 v1.5.2 的运行证据也不能直接替代本版验证。

发布附件建议使用修复目录层级后的 `xiaomi17-audio-v1.5.6.zip`。该文件应为 24,481 字节，`module.prop` 位于根目录，SHA-256 为：

```text
34916f945a53f821370f54c94230ed74266a3d6342ad30b05f047a10dbcd14e2
```

本地另有 `xiaomi17-audio-v1.5.6-device-only.zip`，文件名、模块显示名称及哈希与上述附件不同。发布时应选定一个附件，并使用该附件对应的哈希。

## 7. 实机验收与回退

1. 安装后重启，查看 `/sdcard/Download/xiaomi17_audio_mod_selfcheck.txt`。
2. 确认版本为 1.5.6、开机标记为 `version=1.5.6 ok=1`，检查四份文件及其标签。
3. 核对实际运行的 `music / SPEAKER` 曲线，留意 40,-2613、47,-2346、60,-2196、87,-1832 等预期点；这需要结合实际报告判断。
4. 播放同一段熟悉的鼓点与人声素材，在相同沉浸声设置下比较多个常用音量，检查档位切换、闷声、嗡声和破音。比较音色时尽量匹配听感响度。
5. 再检查常用视频、音乐和游戏应用，以及耳机、蓝牙等日常功能，确认当前系统没有出现回归。

临时排查可以停用模块并重启，但停用不执行卸载脚本，不能保证已设置的持久音效状态同时恢复。完整移除使用模块管理器卸载并重启，卸载脚本会尝试恢复此前保存的状态。需要回退版本时，选择在同一手机与系统上已经验证过的旧包。
